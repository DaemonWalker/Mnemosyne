# Mnemosyne 实施步骤（Steps）

> 整个项目分为 12 个 Step，每个 Step 由一个子 agent 在一次会话中完成。Step 之间严格按顺序执行，前一个 Step 全部勾选后才允许开始下一个。

## 进度记录协议（所有子 agent 必须遵守）

1. **开工前必读**：`docs/requirements.md`、`docs/architecture.md`、`docs/code-style.md`、本文档、`docs/progress.md`
2. 从 `docs/progress.md` 的"当前状态"确认自己该做哪个 Step；若与主对话指派的不一致，先停下来报告
3. **每完成一个小目标立即记录**（不等整个 Step 做完）：
   - 勾选本文档中对应复选框 `[x]`
   - 在 `docs/progress.md` 追加一条日志（时间、Step、子目标、完成内容、变更文件、构建结果、遗留问题）
4. 小目标完成标准：`dotnet build` 全解决方案 0 错误 0 警告 + 该小目标验收条目实际通过
5. 若 token 将尽或遇阻塞无法继续：把当前小目标的**进行状态、已完成的部分、下一步该做什么**写进 `docs/progress.md` 的"断点信息"节，然后停止
6. 整个 Step 完成后：更新 `docs/progress.md` 的"当前状态"，并输出验收清单核对结果
7. **整个 Step 完成后必须 `git commit` 并 `git push`**：
   - 提交信息格式：`step{N}: {Step 标题}（{简要说明}）`，如 `step3: 编辑器内核（打开/保存/编码/高亮）`
   - 提交内容包含本 Step 的全部代码变更 + steps.md 复选框 + progress.md 日志
   - commit 前确认 `dotnet build` 0 错误 0 警告；构建不通过禁止提交
   - push 失败（网络问题等）不阻塞，但必须在 progress.md 日志中记录"commit 成功 / push 失败"

## Step 1 — 项目骨架与基础设施

**目标**：解决方案可构建、可启动空窗口，配置/主题/语言基础设施就绪。

- [x] 1.1 创建 `Mnemosyne.sln` 与项目结构（`src/Mnemosyne`、`src/Mnemosyne.Plugin.Abstractions`、`plugins/` 下三个格式化器项目），按 architecture.md 配置 TFM、Nullable、ImplicitUsings，引入全部 NuGet 包
- [x] 1.2 启动骨架：`App.xaml` 启动流程 + 空白主窗口；单实例（Mutex + 命名管道转发命令行参数）；命令行传文件路径可解析（暂存，Step 3 才用）
- [x] 1.3 `ConfigService`：便携模式 `config/settings.json` 读写（System.Text.Json，`AppSettings` 模型含主题/语言/字体/字号/缩进/大文件阈值等全部设置项）
- [x] 1.4 i18n 基础设施：`LocalizationService` + zh-CN/en 资源，支持运行时切换并通知 UI 刷新
- [x] 1.5 主题基础设施：`Theming/Dark.xaml`、`Theming/Light.xaml` 资源字典 + `ThemeService` 切换

**验收**：窗口能启动；设置修改后落盘、重启生效；主题与语言切换立即生效；构建 0 警告。

## Step 2 — 主窗口布局

**目标**：VSCode 风格三栏布局骨架，尚无真实功能。

- [x] 2.1 左侧活动栏：文件、搜索两个图标按钮（自绘或 Symbol 字体），点击切换侧边栏显隐与内容
- [x] 2.2 侧边栏容器：文件面板、搜索面板占位 UserControl
- [x] 2.3 中间 Tab 区域：样式化 TabControl（深色主题下观感接近 VSCode），带空状态提示页
- [x] 2.4 底部状态栏骨架：行列号/编码/行尾符/语言/缩进/进度条区域占位
- [x] 2.5 主菜单栏 + 快捷键框架：需求 4.11 列出的快捷键全部注册为 RoutedCommand，命令暂绑定到空实现

**验收**：布局比例正确；活动栏切换流畅；快捷键触发对应（空）命令；深/浅主题下均正常。

## Step 3 — 编辑器内核

**目标**：能打开、编辑、保存文件，编码与语法高亮完整。

- [ ] 3.1 `ScintillaHost` 控件封装：字体/字号应用、主题配色应用（含常用 Lexer 的配色表）、行号边栏、当前行高亮、缩进参考线
- [ ] 3.2 打开文件：菜单/命令行/拖拽三个入口 → 新 Tab；同一文件重复打开聚焦已有 Tab
- [ ] 3.3 编码：UTF-8/BOM/UtfUnknown 探测，状态栏显示，手动切换按新编码重载（有未保存修改时先确认）
- [ ] 3.4 保存/另存为（Ctrl+S），脏标记（Tab 标题圆点），关闭脏 Tab 时提示（热退出只兜底进程退出，不关 Tab 场景）
- [ ] 3.5 行尾符：检测 CRLF/LF，状态栏显示，点击弹出转换菜单
- [ ] 3.6 语法高亮：扩展名 ↔ Lexer 映射表；语言选择弹窗（列出全部 Lexer + 搜索框过滤）；状态栏显示当前语言，点击打开弹窗

**验收**：打开/编辑/保存/另存全流程正确；GBK 文件不乱码；编码切换正确；至少 10 种常见扩展名自动匹配高亮正确；弹窗搜索可用。

## Step 4 — 文件树

**目标**：打开文件夹、树形浏览、文件操作。

- [ ] 4.1 打开文件夹（菜单/拖拽/命令行）→ 侧边栏文件树，目录懒加载，排序（目录在前，名称排序）
- [ ] 4.2 FileSystemWatcher 监听增删改，防抖后刷新对应节点
- [ ] 4.3 单击文件 → 打开到 Tab；根节点显示文件夹名，可关闭文件夹
- [ ] 4.4 右键菜单：新建文件/新建文件夹/重命名/删除/在资源管理器中打开；新建与重命名用内联编辑框
- [ ] 4.5 最近打开列表：`RecentFilesService` + 文件菜单展示（文件与文件夹分开），最多 20 条

**验收**：树操作全部生效且磁盘上真实生效；外部改动能自动刷新；最近列表重启后保留。

## Step 5 — 页内搜索与替换

**目标**：当前文档内的查找替换，含三种匹配选项。

- [ ] 5.1 搜索条 UI（编辑器顶部浮层，Ctrl+F 打开，Esc 关闭并聚焦编辑器）
- [ ] 5.2 选项：大小写敏感、全字匹配、正则表达式（三个 toggle 按钮）；选项变化即时重搜
- [ ] 5.3 全部匹配高亮 + 当前匹配区别配色；计数显示（如 3/27）；Enter/Shift+Enter 或按钮上下导航，循环跳转
- [ ] 5.4 替换条（Ctrl+H）：替换当前、全部替换；替换后计数与高亮同步更新

**验收**：三种选项及组合行为正确（含正则特殊字符、中文全字语义）；大文档高亮不卡；替换结果正确。

## Step 6 — 文件夹内搜索

**目标**：侧边栏全文搜索，VSCode 风格。

- [ ] 6.1 搜索面板 UI：关键字输入框、三个选项 toggle、包含 glob 输入框、排除 glob 输入框（占位提示参照 VSCode，如 `*.cs, src/**` 和 `**/bin/**`）
- [ ] 6.2 扫描引擎：后台 Task 递归遍历，glob 匹配包含/排除规则，跳过二进制（按内容嗅探）与默认排除项（.git、bin、obj、node_modules）；可取消；新搜索取消旧搜索
- [ ] 6.3 结果增量推送 UI：按文件分组的可展开树，每条结果显示行号与匹配行文本（匹配部分高亮）
- [ ] 6.4 双击结果 → 打开文件 Tab、跳转对应行并选中匹配文本
- [ ] 6.5 结果统计（x 个结果 / y 个文件）、空结果与未打开文件夹的提示态

**验收**：包含/排除规则正确；中文内容搜索正常；搜索 10 万行级目录 UI 不卡（虚拟化）；取消即时生效。

## Step 7 — 编辑体验增强

**目标**：多光标、缩进、Tab 交互等体验项。

- [ ] 7.1 多光标：开启 MultipleSelection/AdditionalSelectionTyping/矩形选择；实现 Ctrl+D（选中下一个相同词并加光标，Esc 退回单光标）
- [ ] 7.2 缩进：设置项（Tab/空格、宽度）；打开文件时按内容自动检测缩进风格；状态栏显示并可直接点击切换
- [ ] 7.3 自动换行开关、空白字符可视化开关（视图菜单 + 设置项）
- [ ] 7.4 Tab 交互：拖拽排序、中键关闭、右键菜单（关闭/关闭其他/关闭右侧/在资源管理器中打开/复制路径）

**验收**：多光标输入/删除/列选择行为正确；Ctrl+D 边界（词尾、无匹配）正确；检测缩进不误判；Tab 交互全部生效。

## Step 8 — 大文件加载

**目标**：边读边显示 + 进度条。

- [ ] 8.1 阈值判断：超过设置阈值（默认 50MB）进入大文件模式
- [ ] 8.2 `FileService` 分块异步读取（1MB/块，注意不在多字节字符中间切断 UTF-8），`ScintillaHost` 逐块 AppendText
- [ ] 8.3 状态栏进度条 + 百分比 + 取消按钮；取消后关闭该 Tab 或保留已加载部分（需用户选择提示）
- [ ] 8.4 加载期间只读、Lexer 关闭；完成后启用高亮与编辑

**验收**：100MB 测试文件可见内容滚动填充、进度准确、取消可用、加载完成后高亮正常；小文件走原路径不受影响。

## Step 9 — 插件系统与格式化器

**目标**：插件加载机制 + 三个内置格式化器。

- [ ] 9.1 Abstractions：`ICodeFormatter` 接口（含 XML 文档注释）、`FormatterOptions`、元数据属性
- [ ] 9.2 `PluginService`：扫描 `plugins/` 目录反射加载，逐插件隔离异常，失败记日志；提供按语言查询
- [ ] 9.3 JSON 格式化器（System.Text.Json 解析后美化输出，缩进跟随当前编辑器设置）
- [ ] 9.4 XML 格式化器（XDocument 美化，保留声明与注释）
- [ ] 9.5 HTML 格式化器（容错解析，不规则 HTML 不报错；可自行实现缩进排版）
- [ ] 9.6 UI 入口：编辑菜单与编辑器右键"格式化文档"，按当前语言匹配插件，无匹配时禁用并提示

**验收**：三个格式化器对合法/非法输入行为正确（非法输入给错误提示且不破坏原文）；删除某插件 dll 后其余功能不受影响。

## Step 10 — Markdown

**目标**：编辑高亮 + 预览新 Tab。

- [ ] 10.1 Markdown Lexer 高亮配色（深/浅主题各一套）
- [ ] 10.2 Markdig → WPF 渲染器：标题/段落/列表/代码块（带语法着色的纯文本着色即可）/引用/表格/链接/图片（本地相对路径）
- [ ] 10.3 "打开预览"入口（编辑器右上角按钮 + 快捷键 Ctrl+Shift+V）：新 Tab 展示渲染结果
- [ ] 10.4 源文件保存后预览自动刷新；源 Tab 关闭时预览 Tab 一并处理

**验收**：GFM 常用语法渲染正确；刷新不闪烁；图片加载失败有占位提示。

## Step 11 — 设置界面与热退出

**目标**：设置窗口 + 热退出与会话恢复。

- [ ] 11.1 设置窗口（Ctrl+,）：字体（系统字体列表）、字号、主题、界面语言、缩进、大文件阈值、自动换行、空白字符显示；改动即时应用并落盘
- [ ] 11.2 热退出：脏文档内容实时（防抖）暂存 `cache/hotexit/`；进程退出不提示；正常保存后清除对应暂存
- [ ] 11.3 会话恢复：`cache/session.json` 记录打开的 Tab（文件路径 + 光标位置）、打开的文件夹、活动 Tab；启动时恢复
- [ ] 11.4 外部修改检测：已打开文件在磁盘被改时提示重新加载/保留

**验收**：杀进程后重启完整恢复（含未保存修改）；会话恢复光标位置正确；外部修改提示正确。

## Step 12 — 性能打磨与发布

**目标**：达成启动指标，产出便携发布包。

- [ ] 12.1 启动优化审计：测量冷启动（无会话/有会话两种情况），将窗口显示前的非必要工作全部延后；插件扫描改异步
- [ ] 12.2 ReadyToRun 发布配置与发布脚本（输出单文件夹便携包，含 plugins/、config/ 初始结构）
- [ ] 12.3 全功能回归走查清单执行（按 requirements.md 逐条核对并记录结果）
- [ ] 12.4 修复走查发现的问题；最终 `dotnet build` 0 警告 + 发布包冷启动 1 秒内（普通 SSD 机器）

**验收**：回归清单全绿；发布包解压即用。
